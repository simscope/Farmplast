# Farmplast Pennsylvania Climate Control — работа на домашнем MSI

**ВЫПОЛНИ НА MSI**, не останавливаясь после очередной инвентаризации.

Проект: `simscope/Farmplast`, рабочая ветка `work/pa-climate-auto-msi-20261110`, каталог `integrations/pa-climate-auto-v3`.

## Принято владельцем

- **MSI — домашний сервер.** На него не подключают ESP32 по USB. Не ищи COM-порты на MSI.
- **ESP32 прошивается однократно на рабочем Windows-компьютере**; затем используется OTA с MSI. Нынешний `automation/Auto-Add-ESP32.ps1` НЕ готов для запуска на рабочем компьютере: он требует конфиг/админский ключ локально на MSI. Не выдавай его за готовое решение.
- **Вчерашнее управление реле уже проверено владельцем**. Никаких дополнительных искусственных блокировок или повторных формальных испытаний. Исходник версии PA Climate 1.2.0 и фактический GPIO/полярность пока не представлены в репозитории; не приписывать новой 2.0.0 эквивалентность, пока не сохранена реальная рабочая конфигурация.
- На одной ESP32 — два DS18B20 на общей 1-Wire линии GPIO27, автообнаружение ROM, управление по средней T1/T2, аварии по фактическим данным.
- **Не менять дизайн** действующей страницы `farmplast.vercel.app/monitoring/pa/climate`: основная Temperature = T1, вместо Wi-Fi · dBm = T2, средняя для управления; сохранить существующие PIN, общий и индивидуальные setpoint, +/- и Save, AUTO/MANUAL/OFF, HEAT и стили. `web/ClimateControlMsi.jsx` — альтернативный макет, **не заменять** им live-страницу.
- Никаких новых серверов, отдельного порта 18177, Docker, Supabase-таблиц, Tailscale для ESP32, фиктивных URL, вымышленных сертификатов, `setInsecure()` или демонстрационных данных.

## Выполнить по порядку, без пауз ради новых согласований

1. **MSI backend.** Найти код действующего HTTP gateway на MSI. Положить исходники пакета на MSI в `E:\SimScopeData\Farmplast\Climate\module` без развертывания второй службы. Подключить `server/app.mjs` как `/climate` в реально используемом backend (адаптер Express использовать только если сервер действительно Express). Не менять другие маршруты. Подключить существующее хранилище MSI в пределах разрешенной схемы — никакой дополнительной базы или таблицы.
2. **HTTPS ingress.** Найти уже существующий публичный HTTPS-вход на MSI; если его нет, подготовить защищённый reverse proxy для `/climate/v1/exchange` и подписанного `/climate/v1/firmware/*`. Изолировать admin API: его нельзя публиковать напрямую. Не открывать PostgreSQL, Supabase Studio, AI Manager. Не использовать Tailscale для ESP32.
3. **Рабочий компьютер.** Переделать onboarding на две стороны: MSI выдаёт через авторизованный существующий веб-интерфейс одноразовую регистрацию и уникальные секреты, а Windows-утилита по USB определяет MAC/COM, сохраняет резервную копию, заливает единый проверенный .bin, записывает настройки в NVS и подтверждает реальную телеметрию MSI. На рабочий компьютер НЕ копировать постоянный MSI admin key, `climate.env` или приватное хранилище. Не требовать ручного ввода URL, JSON, CA или SQL. Wi-Fi Pennsylvania вводится только один раз и сохраняется через Windows DPAPI.
4. **Live Farmplast.** Текущий деплой Vercel содержит новый `ClimateControl.jsx`, `ZoneOne.jsx`, `ClimateProgramming.jsx`, `api/pa-zone1.js`, отсутствующие в GitHub main. Восстановить **реальные исходники опубликованной версии** через доступный Vercel API/CLI, не заменять их старой веткой. Изменить только отображение T1/T2 и подключение к MSI через существующую авторизацию. Новые данные должны идти с MSI; стиль, PIN, кнопки и остальные страницы без изменений.
5. **Проверка end-to-end.** Тесты: 2 DS18B20 → среднее → сервер MSI → существующая карточка T1/T2, изменение уставки с PIN → ACK на устройстве → изменение HEAT; обрыв одного датчика и Wi-Fi, возврат связи; одно реальное OTA обновление и проверка восстановления. Отказ от внешних проверок оборудования, уже подтверждённых владельцем; проверять только интеграцию новой прошивки.
6. **Четыре платы.** После реального GO первой ESP32 прошивка для оставшихся трёх одинаковая, без ручного редактирования .ino и без повторного полного тестового цикла на каждой.

### Готовые исходники и подтверждённые тесты

- `firmware/FarmplastClimate`: версия 2.0.0 собирается в GitHub Actions для ESP32-WROOM-32E-N4; включено управление реле по решению владельца.
- `web/climateUiData.mjs` — только адаптер T1/T2, не альтернативная страница; unit-тесты сохранения положения данных проходят.
- `server/app.mjs` + тесты Node проходят локально. Это не означает установки на MSI или успешного физического OTA.
