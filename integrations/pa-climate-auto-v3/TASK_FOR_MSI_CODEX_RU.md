# Задание Codex, выполняемое ЛОКАЛЬНО на домашнем MSI

Цель: в существующий MSI-сервер Farmplast добавить модуль Climate Control и функцию «Добавить контроллер», исключив ручной ввод параметров для каждой ESP32.

**НЕ создавать новый сервер или службу**. Запрещены новые Docker контейнеры, новые базы, новые таблицы Supabase, новые входящие порты, отдельный процесс `node server.mjs`, Tailscale в цепочке ESP32. **Не перепрошивать действующую Zone 1**. Не менять PA Climate 1.2.0 и production сайт, пока не восстановлены подтверждённые исходники и не проверена совместимость.

1. Найти реальный работающий HTTP gateway на MSI по процессу и конфигурации; получить фактический порт и исходный код. Не полагаться на предположения о языке/платформе. Локальный Supabase уже есть — не устанавливать повторно.
2. Подключить `module/server/app.mjs` через `createClimateHandler` или `createClimateRoute` **в этот уже существующий backend** под `/climate` (используй `integration/attach-express-existing-server.mjs` только если сервер реально Express). Сохранить остальные маршруты.
3. `E:\SimScopeData\Farmplast\Climate\climate.env`: настроить `CLIMATE_LOCAL_BASE_URL` по факту и `PUBLIC_ORIGIN` по действительному публичному HTTPS ingress. Не выдумывать URL; не использовать `setInsecure()`.
4. Защитить публичную трассу: **НЕ** пропускать `GET/POST /climate/v1/admin/*` напрямую от интернета. Разрешить устройству лишь аутентифицированный exchange и подписанные загрузки, разрешив `/healthz` для проверки. Админские команды идут с проверкой существующего Farmplast JWT/allowlist через серверный API, ключ не выдаётся в браузер.
5. Пройти `node --test automation/onboard.test.mjs server/tests/*.test.mjs`; проверить реальные HTTP запросы на существующий gateway. Проверить сохранность данных и отсутствие старого процесса `18177`.
6. Автоматизатор `module/automation/Auto-Add-ESP32.ps1` уже делает обнаружение COM/MAC, свободной зоны, уникальные ключи, полное резервирование 4 MB, компиляцию единого бинарного образа, его прошивку и индивидуальное NVS-провижининг по USB; запустить на **новой** тестовой ESP32 с изолированным питанием. Реле разрешено программно (`RELAY_TESTED_AND_ENABLED=true`) по решению владельца; не добавлять искусственную блокировку. GPIO и активную полярность оставить настраиваемыми, фактическая разводка ещё не проверена.
7. Восстановить исходники реально опубликованной страницы Farmplast (не старой GitHub main), сохранить PIN, авторизацию и всю разметку, заменить только `Wi-Fi · dBm` на T2, показать T1 и среднюю; данные берутся с MSI.
8. Подтвердить 2 температурных датчика, отключение обоих, одиночную неисправность, команды/ACK, перезагрузку, потерю Wi-Fi, подписанный OTA и реальное восстановление после неудачной прошивки. До подтверждения OTA не выдавать GO.

**Критерий готовности:** следующая новая ESP32 добавляется через один запускаемый мастер без ручного переписывания `.ino`, JSON-токенов, URL, CA или SQL. Единственный ввод: пароль Wi-Fi PA на первой плате (затем сохранён DPAPI), выбор COM при нескольких и подтверждение физически нового контроллера. На MSI использован только существующий сервер/инфраструктура.

Отчёт владельцу — коротко: что работало раньше, что конкретно изменено, что протестировано, чему ещё нет физического подтверждения. Никаких больших аудитов вместо действий.
