# Веб-интеграция в существующий Farmplast — требования к объединению

ВНИМАНИЕ: Production Vercel от 10 ноября 2026 содержит более новые файлы `ClimateControl.jsx`, `ZoneOne.jsx`, `ClimateProgramming.jsx`, `/api/pa-zone1`, которых **нет** в текущей GitHub `main` и ветке `codex/pa-dashboard-production`. Не делать `git checkout main` и `vercel --prod` поверх действующей версии.

## Обязательное сохранение внешнего вида (решение владельца 10 ноября)

**Не заменять существующую страницу целиком компонентом `ClimateControlMsi.jsx`**: это отдельный макет, который потеряет реально работающие стили, PIN, форму общей уставки и кнопки. Использовать исходник опубликованной на Vercel страницы, сохранив DOM/CSS и маршруты.

- В карточке зоны оставить крупное поле **Temperature** на старом месте и показывать в нём T1 (`sensor_1_f`).
- На том же месте, где сейчас **Wi-Fi · dBm**, заменить иконку и подпись на **Temperature 2** и вывести T2 (`sensor_2_f`); никакого блока/карточки сверх существующей структуры.
- Средняя `temperature_f=(T1+T2)/2` применяется для регулирования на ESP32 и проверяется сервером; не выдавать её за температуру одного из датчиков. Её можно показать в существующей диагностике без изменения основной карточки.
- Сохранять настройку общего Setpoint, индивидуальные уставки с +/- и кнопкой Save, PIN, AUTO/MANUAL/OFF и индикацию HEAT, обработку Offline и все существующие стили.
- Для потери одного датчика: оставшийся отображается, другой — «—», регулирование продолжается по доступному. При двух потерянных: «—», авария, HEAT OFF. При Offline не показывать старые показания как текущие.
- Для преобразования ответа MSI API в отображаемые поля использовать `climateUiData.mjs` и `climateUiData.test.mjs`. Этот адаптер **не заменяет UI**.
- Не считать новую страницу опубликованной до получения и сравнения текущего source Vercel и проверок интерфейса.

Новые подготовленные файлы, которые можно перенести в **восстановленный исходник текущей опубликованной версии**:

1. `api-pa-climate-msi.js` → `client/api/pa-climate-msi.js`.
2. `ClimateControlMsi.jsx` → `client/src/components/monitoring/pa/ClimateControlMsi.jsx`.
3. `ClimateProgrammingMsi.jsx` → `client/src/pages/ClimateProgrammingMsi.jsx`.

Заменить **только** климатические маршруты и компоненты после восстановления текущего исходника; сохранить структуру PA, PIN авторизации изменения температуры, существующий дизайн/кнопки и другие разделы. Новые компоненты в пакете являются работающей автономной альтернативой с MSI API, но при объединении с текущей страницей НЕ удалять её PIN и остальные рабочие механизмы. Из текущего блока `Wi-Fi · dBm` убрать только эту метрику и показать `Temperature 2` (`sensor_2_f`), крупный блок `Temperature` показывает `sensor_1_f`. Среднее `temperature_f` используется для управления и диагностики.

Пример интеграции с существующим React route (полную маршрутизацию менять только после сравнения с текущей source-сборкой):

- Route `/monitoring/pa/climate`: `ClimateControlMsi` либо адаптированный существующий `ClimateControl` с новым API.
- Route `/monitoring/pa/climate/programming`: `ClimateProgrammingMsi` либо адаптированный текущий `ClimateProgramming` с сохранением USB-прошивки.

Vercel environment (только server-side значения):

- `PA_CLIMATE_MSI_BASE_URL`: действительный HTTPS endpoint MSI с путём `/climate`; адрес не угадывать;
- Административный ключ MSI не передаётся Vercel или браузеру. Прокси передаёт существующий пользовательский JWT в `/climate/operator/*`; MSI повторно проверяет JWT и allowlist.
- `PA_CLIMATE_ALLOWED_USER_IDS`: UUID допущенных операторов через запятую; по умолчанию используется существующий `SACS_SSO_ALLOWED_USER_IDS` этого проекта;
- `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`: существующие, использовать для проверки JWT, не менять.

Ни одно значение не должно попасть в `VITE_*` или JS клиента, кроме уже публичного anon key.

Браузер обращается к `/api/pa-climate-msi` на Vercel. Этот API аутентифицирует пользователя существующим Supabase JWT, сверяет UUID с allowlist и затем пересылает запрос в MSI. Данные и `.bin` хранятся ТОЛЬКО на MSI. Веб-сервер Vercel является лишь прокси. На MSI новый экземпляр Supabase не создаётся; существующие системы Farmplast и чиллеров не изменяются.

Для старта объединения нужна текущая source-копия web-приложения (с CLI-deploy), а не более старая ветка GitHub. Работу в production выполнять после того, как локальные тесты на MSI и физический тест датчиков прошли.
