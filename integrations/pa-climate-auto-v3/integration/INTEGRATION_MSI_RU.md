# Однократная интеграция в существующий MSI — без второго сервера

## Факты, а не предположения

Работающий MSI и локальный Supabase известны. Конкретный исходник приложения, которое сегодня слушает HTTP-запросы на MSI, из этого архива **не виден**. Поэтому нельзя вслепую менять `18765`, `18000` или любые другие порты и нельзя поднимать отдельный `node server.mjs` на `18177` (тот вариант был ошибочным).

Код `server/app.mjs` экспортирует:

- `createClimateHandler({dir,adminKey,publicOrigin})` — низкоуровневый Node request handler;
- `createClimateRoute(...)` — middleware для входящего маршрута `/climate`, **без** `.listen()`;
- `createClimateServer(...)` — только обратная совместимость автоматических тестов, **не использовать для установки на MSI**.

Если текущий MSI gateway — Node/Express, достаточно подключить `integration/attach-express-existing-server.mjs` **в уже существующем приложении**, до парсеров request body. Этот модуль не запускает новых служб. Если gateway написан на другом стеке, Codex адаптирует к реально существующему процессу после изучения его кода; не заменять приложение ради адаптера.

Снаружи маршрутизировать только `https://<реальный-домен>/climate/*` к имеющемуся HTTP gateway и его `/climate/*`. Внутри MSI конфигурация должна содержать фактический loopback-адрес этого сервера, например `http://127.0.0.1:<фактический порт>/climate`. Имя хоста и порт **не угадывать**. `PUBLIC_ORIGIN` должен точно совпадать с публичным `https://.../climate`.

MSI Edge/Auth/PostgreSQL/Studio/AI Manager не публиковать отдельными адресами и портами. Токены устройств уникальны и хранятся в `E:\SimScopeData\Farmplast\Climate\provisioning` с ограниченными ACL. Ключ администратора никогда не возвращать в браузер. На public ingress запросы `v1/admin/*` должны быть закрыты внешним роутером; admin API доступен только через loopback и веб-прокси с действующей авторизацией. Не публиковать `/climate/v1/admin` на устройственную публичную точку входа без серверного ограничения маршрута.

### Обязательная безопасность и соответствие

1. Проверить, что MSI действительно имеет доступный HTTPS public ingress (не Tailscale). Если его нет, сначала настроить точку входа безопасным способом на существующем сервере; никакой несуществующий URL не генерировать.
2. Включить и проверить локальный маршрут `/climate/healthz` и `/climate/v1/admin/zones` (второй должен отвергать неавторизованных клиентов).
3. Обеспечить недоступность Admin API снаружи. Общедоступны только `healthz`, `v1/exchange`, подписанный `v1/firmware/…`, с проверками внутри handler. Admin запросы из сайта передаются в MSI по отдельному серверному защищённому маршруту, с проверкой Farmplast JWT + операторского допуска; не размещать admin key в фронтенде.
4. Убедиться в сохранении существующих страниц и локального Supabase. Никаких новых контейнеров, SQL-таблиц, постоянных Node listeners и портов.
5. Только после этого добавить одну новую ESP32 без нагрузки и проверить две DS18B20, среднее, offline, потерю датчиков, команды и OTA. Не прошивать вчерашнюю Zone 1 автоматически.

> Не объявлять работу завершённой, пока реальный MSI gateway не интегрирован, настоящий HTTPS URL не установлен и тестовая ESP32 физически не подключилась.
