# Замена контроллера и первоначальное назначение BF:90

Production сайта основан на актуальном Git main `50da67c2355912bfdbdc937030f29ce607e91cd8`, а не на прежнем CLI-снимке. Изменены только PA Climate API/transport и Programming/диагностика. HR, Payroll и NJ не менялись.

На MSI используется прежний main worker `supabase-edge-functions` за Envoy `127.0.0.1:18000`. Состояние остаётся в `E:\SimScopeData\Farmplast\Climate\data\climate-state.json`. Новых служб, портов, контейнеров, баз и таблиц нет. Зона и её desired/settings/history сохраняются независимо от платы.

## Действие владельца на Windows возле платы

1. Войти в Farmplast своей существующей учётной записью. Открыть PA Climate → Programming & diagnostics → **Replace controller · Zone 1**.
2. Ввести действующий PIN владельца и нажать **Prepare replacement**, затем **Download / resume Windows USB setup**. Для свободной Zone 1 заранее указан ожидаемый ID `PA-CLIM-209BA98DBF90`. Пароль/PIN не включаются в ZIP или URL.
3. Распаковать ZIP и запустить **Run-Replacement.cmd** на Windows-ПК с BF:90. COM выбирается только при нескольких портах. IO0 должен быть отпущен для чтения стартового UART; EN нажимается по инструкции мастера. MAC/модель/версия определяются автоматически.
4. Безопасное ожидание назначения требует прошивки **pa-climate-msi-2.1.0**. Если версия старее, мастер предложит UPDATE: при отключённой силовой нагрузке он проверит ROM MAC, сохранит все 4 MB, проверит dual-OTA разметку, обновит только выбранный application slot и проверит SHA256 чтением обратно. NVS не стирается. Это USB-обновление, не проверка OTA/отката.
5. Мастер использует сохранённые DPAPI Wi-Fi; на новом ПК спросит пароль. Для BF:90 исходная целевая сеть — `Kinetic_900085`; компьютер может находиться в другой сети. CA извлекается из проверенной Windows TLS-цепочки, адрес MSI и ограниченный токен операции приходят в ZIP. Ручных URL/ключей/CA/SQL нет.
6. После USB PROVISION PASS дождаться **MSI ONLINE / OFF / target ACK confirmed**. При недоступной целевой сети операция остаётся pending: повторить тот же мастер после подключения платы к Wi-Fi, не создавать вторую регистрацию.
7. На сайте сверить Zone 1, старый и новый Device ID. **Confirm replacement** доступна только после свежей телеметрии нового устройства с OFF и ACK настроек; два датчика для этого не требуются. По умолчанию режим остаётся OFF. Восстановление сохранённого режима выбирается явно, а MANUAL ON требует отдельного подтверждения.

## Защита и восстановление

Создание, скачивание, подтверждение и отмена проходят существующие JWT/allowlist/роль/PIN на API сайта. PIN не заменяет вход. Ограниченный capability разрешает Windows только чтение и подготовку одной операции, но не подтверждение замены, отопление, OTA или admin API. Срок 24 часа; повторное скачивание после PIN продлевает доступ.

Повтор prepare возвращает те же зашифрованно сохранённые ключи. Новая плата staged и держит OFF до получения `registration_state=active`. Коммит одной атомарной записью сохраняет зону, переключает назначение, отзывает старые ключи и отменяет её ожидающие OTA. Старые телеметрические записи остаются с исходными device_id/zone_id; история замен хранится в том же JSON. При ошибке записи сохраняется прежнее активное назначение. Параллельная операция той же зоны отклоняется.

BF:90 нельзя считать назначенной, ONLINE или подтвердившей NVS 50 °F до реальной работы мастера и последующей телеметрии. Сборка, тестовые ACK и проверка изолированного хранилища не являются аппаратным подтверждением. OTA и восстановление после неудачной прошивки отмечаются отдельно.
