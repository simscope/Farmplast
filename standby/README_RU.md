# Резервный Payroll на MSI

Рабочая система остаётся на https://farmplast.vercel.app и Supabase Farmplast eeobivvwjzakbweluwtm. На MSI подготовлен отдельный сайт https://msi.tail4626fb.ts.net:9444. Для доступа нужен подключённый Tailscale. Вход — существующие email и пароль на дату копии; ключи API у резерва собственные, поэтому рабочие сеансы Supabase не переносятся в браузер автоматически.

## Текущее состояние

Режим standby: сведения, фотографии, часы, история выплат и расчётные листы доступны для чтения. Верхняя полоса показывает режим и дату копии. Изменение сотрудников, выплаты, выдача чеков, команды ZKT и отправка данных в SACS запрещены шлюзом; 29 бизнес-таблиц дополнительно защищены триггерами в PostgreSQL. Исходные RLS и права сохранены. Например, payroll_checks разрешён исходными политиками ролям owner/company_admin; данные всех 1933 чеков восстановлены, тестовому admin эти политики не дают прямое чтение таблицы.

Восстановлены определения и содержимое 67 таблиц, 73 сотрудника, 1224 выплаты, 1933 чека, две учётные записи и все 64 фотографии. Проверка сравнила контрольные суммы всех строк перед добавлением защиты резерва. Приёмка API отдельно проверила вход, обновление сеанса, выход, чтение, все фотографии через защищённый шлюз и отказ записи. В Chrome проверены список сотрудников, фотографии, карточка, история выплат и Paystub details. Реальных выплат и команд терминалам при проверке не создавали.

Полный новый backup + restore + standby refresh выполнен от SYSTEM: результат 0, снимок 18 ноября 2026 01:02:47 UTC (17 ноября 20:02 New York), 49 360 строк. После удаления тестового пользователя контрольные суммы всех 29 бизнес-таблиц остались прежними. Повторный системный запуск сохранил более свежий снимок; конкурирующий refresh с занятым lock отказал без изменения статуса. Проверены 10 тестов backup/gateway/SACS, 34 проверки Payroll/SACS и обе сборки клиента. Подробности без персональных данных: [acceptance-20261117.json](acceptance-20261117.json). [Страница входа при проверке](acceptance-login.jpg).

Еженедельно в понедельник 03:00 MSI (Atlantic Standard Time) Windows-задание Farmplast-Payroll-Weekly-Backup создаёт, расшифровывает для проверки и восстанавливает архив, затем обновляет standby. Архивы не удаляются. При недоступности Supabase аварийное восстановление возможно на дату последней успешной копии: изменения после неё могут отсутствовать. При плановом переходе делается свежая финальная копия после блокировки записей на исходнике.

Веб-сборка резерва использует VITE_PAYROLL_STANDBY=1. Рабочая Vercel-сборка с обычными переменными остаётся на Supabase. В резерве вместо Realtime используется опрос списка каждые 30 секунд. Функции пересчёта присутствия и часов в standby возвращают отметку о чтении снимка и не изменяют его.

## Файлы и запуск

MSI: E:\SimScopeData\Farmplast\PayrollStandby.

- private: собственные ключи и compose, серверные настройки SACS, оригинальные и подготовленные настройки мостов. Доступ SYSTEM и MSI\sandr.
- runtime: статус, собранный сайт, общедоступный anonymous key и экспорт задания.
- releases: проверенные фотографии каждого поколения. Успешные поколения сохраняются для отката.
- work: закрытая рабочая область восстановления. Успешный запуск удаляет расшифрованный дамп.
- scripts: шлюз, обновление, проверки и инструменты будущего перехода.

Отдельные контейнеры farmplast-payroll-db/auth/rest/storage используют собственную сеть и тома. Образы закреплены SHA-256; PostgreSQL 17.6 совместим с исходником. Порты 18622/18623/18621/18624 доступны только на loopback. Шлюз слушает 127.0.0.1:18640 и запускается при старте Windows заданием Farmplast-Payroll-Standby-Gateway от LOCAL SERVICE с чтением runtime/scripts/releases/app. Эта служба не имеет доступа к private и Docker. Веб-порт 9444 опубликован только внутри tailnet. Существующие адреса Hvac, AI Manager, телеметрии и PA climate сохранены; новый Funnel не включался.

Контейнеры настроены restart unless-stopped. Docker Desktop и Tailscale должны работать на MSI. Перезагрузка всего сервера для приёмки не выполнялась.

Проверка без изменения режима:

```powershell
Invoke-RestMethod 'https://msi.tail4626fb.ts.net:9444/healthz'
& 'C:\Program Files\nodejs\node.exe' 'E:\SimScopeData\Farmplast\PayrollStandby\scripts\activate-standby.mjs'
```

Без --activate помощник только показывает готовность, возраст снимка и наличие будущей блокировки исходника.

## Порядок настоящего перехода — сейчас не выполнен

Переход выполняется только по отдельной команде владельца. Нельзя одновременно вести рабочую зарплату на двух базах.

1. Предупредить операторов, остановить NJ и PA через StopCloud/stop-cloud с явным --execute/-Execute PAYROLL-MSI-CUTOVER. Скрипты проверяют исходные хеши, а изменившиеся настройки требуют новой подготовки. Пока ничего не устанавливается в живые .env.
2. На исходном Farmplast применить подготовленный fence-source.sql с административным доступом и проверить frozen=true. Этот SQL сейчас не применён. Он блокирует бизнес-записи, сохраняя чтение для финального snapshot. Функция и таблица находятся в уже копируемой private-схеме и входят в свежий дамп. На MSI SQL проверен в полностью отменённой транзакции.
3. На MSI выполнить weekly-payroll.mjs --fresh, дождаться проверенного архива и ready=true. Проверить данные и дату; activation требует снимок замороженного исходника не старше 30 минут. Если Supabase уже недоступен, остановиться и отдельно согласовать восстановление старого снимка и возможную потерю последних изменений.
4. На MSI выполнить activate-standby.mjs --activate --ack-bridges-stopped. Он закрывает HTTP-доступ на время смены режима, снимает локальную защиту, отменяет унаследованные pending/running команды и pending sync сотрудников, устанавливает закрытые серверные параметры. При неполной активации доступ остаётся закрытым для ручного восстановления. Исходник остаётся замороженным.
5. Выполнить ActivateMsi/activate-msi на обоих мостах с явным подтверждением. Проверить режим active, доступ и свежие реальные punches. Рабочую страницу открыть по частному адресу MSI; подключение основного Vercel-адреса при необходимости выполняется отдельно. Коды и ключи не передавать в чат.
6. Перед возобновлением рабочих выплат настроить еженедельное резервное копирование нового рабочего MSI. Текущий weekly-payroll.mjs намеренно прекращает Cloud-копирование/refresh при mode=active или activating и выдаёт ошибку для уведомления. Это обязательная часть будущего перехода; сейчас по задаче копии идут именно из Supabase.

Для отката сначала остановить MSI-мосты и запретить записи на MSI. Если на MSI уже появились рабочие изменения, сначала выгрузить и согласовать их перенос; старая облачная копия сама не получит эти изменения. Только затем разрешить записи Cloud и восстановить cloud.env через RollbackCloud/rollback-cloud с явным подтверждением остановки MSI. Автоматического переключения туда-обратно нет.

Обновляющий скрипт отказывается восстанавливать Cloud поверх active/activating. Архивы, ключи и работающие данные Supabase при этой подготовке не удалялись.
