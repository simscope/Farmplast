# Две бочки: подготовка USB-переключения

Пакет `barrels-msi-1` скомпилирован для Waveshare ESP32-S3-Touch-LCD-7: ESP32-S3, flash 8 MB, PSRAM OPI, USB CDC. Он ещё не установлен. Реальная плата и соответствие исходника установленной версии пока физически не проверены.

Исходник владельца: `D:\Farmplast\Tank-Barrel1\Barel2\Barel2.ino`, SHA-256 `369a4e2aafe61d0204c0ec7936f9565df4d53bea3a37e69afc90e10540762124`. Пины RX15/TX16, Modbus 9600, адреса датчиков 1/2, калибровки и экран сохранены. Изменён транспорт: HTTPS443 сайта Farmplast → MSI, отдельный ключ, проверка сертификата GTS Root R1. Передаются только действительные проценты раз в 15 секунд. Ошибка одного датчика не мешает передаче второго; 0% является допустимым показанием. Диагностические блоки значений и полный JSON из Serial убраны.

В прошивке есть Wi-Fi и ключ контроллера. Пакет и резервную копию flash хранить в закрытой папке владельца. В Git и публичные загрузки их не помещать.

## Когда появится доступ к контроллеру

1. Сверить модель платы, 8 MB flash, PSRAM OPI и подключение обоих датчиков с исходником. Проверить физические стороны: Modbus 1 — правый, Modbus 2 — левый. На сайте историческое соответствие сохранено: экранная бочка 1 ← BARREL-NJ-02, экранная бочка 2 ← BARREL-NJ-01.
2. Подключить плату к USB компьютера с этим пакетом. Определить её COM-порт в диспетчере устройств. Не выбирать первый порт автоматически. Закрыть Serial Monitor. Чтение через esptool временно перезапускает контроллер.
3. Проверить пакет без подключения: `powershell -NoProfile -ExecutionPolicy Bypass -File .\install-barrels-usb.ps1`. Этот запуск не открывает COM. Параметр ExecutionPolicy относится только к данному процессу с проверенным локальным скриптом; настройки Windows не меняются.
4. Выполнить идентификацию: `powershell -NoProfile -ExecutionPolicy Bypass -File .\install-barrels-usb.ps1 -Port COM7 -Inspect`, заменив COM7 на фактический порт. При другой модели/памяти остановиться и пересобрать под фактическую плату.
5. После проверки платы и исходника: `powershell -NoProfile -ExecutionPolicy Bypass -File .\install-barrels-usb.ps1 -Port COM7 -Install -BoardConfirmed -SourceConfirmed`. Скрипт сначала сохраняет полные 8 MB flash в закрытую папку `recovery-*`, затем сравнивает существующую таблицу разделов с пакетом. При несовпадении ничего не записывает — потребуется отдельная подготовка под реальную разметку.
6. При совпадении записываются только приложение и служебный выбор app0; загрузчик, таблица разделов, NVS, калибровки и файловая система сохраняются. Полное стирание не выполняется. После записи esptool проверяет содержимое. При ошибке остановиться; резервную копию не публиковать.
7. Проверить оба показания на локальном экране и прямое получение на MSI (`transport: direct`, оба BARREL онлайн). Только после этого добавить BARREL-NJ-01 и BARREL-NJ-02 к серверному списку `NJ_TELEMETRY_MSI_ASSETS` в Vercel, проверить сайт и удалить разрешённые старые строки телеметрии бочек из Supabase.

USB-сценарий проверен только без оборудования: сборка, контрольные суммы и автономная валидация пакета. Работа на физической плате, резервное копирование, запись и восстановление ещё не испытаны. Если требуется восстановление, использовать сохранённую исходную flash только для той же платы после отдельной проверки её защиты и питания; автоматического стирания или восстановления скрипт не делает.

Настройки платы основаны на [документации ESP32_Display_Panel для Waveshare](https://github.com/esp-arduino-libs/ESP32_Display_Panel/blob/master/docs/board/board_waveshare.md). Она не заменяет проверку конкретной платы на месте.
