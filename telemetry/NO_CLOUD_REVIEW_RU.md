# Удаление всех действующих объектов чиллеров из Supabase

Телеметрия и control/OTA работают на MSI. Локальная конфигурация включена 17 ноября 2026 около 04:21 UTC (16 ноября, 23:21 America/New_York): mode=local, свойства cloud нет. Все три реальных потока direct онлайн. Общий вход Farmplast и две бочки остаются действующими частями Supabase до их отдельного переноса. Окончательная очистка выполнена около 04:31 UTC после явного подтверждения владельца с принятием USB-ограничения CH3. Все пять устройств проверены онлайн после удаления.

CH1 и CH2 приняты на MSI-2. CH1: задание `ab6dee5e-08a4-4a62-9584-bfd0bbb89c3c`, новая загрузка `7e3bce5431606e490c849f14a1e0e867`; CH2: `7cd31e84-5c90-4ddc-a4f0-4a1746a25099`, загрузка `10b551f5b36094185c8e6ff7596a1ce9`. CH3 остаётся на MSI-1, загрузка `0833574a0d3c232631975ac5c2ec5268`. Передача измерений MSI-1 полностью совместима с локальным control exchange. Только активные отчёты OTA и загрузка следующих прошивок в ней имеют старый адрес Cloud; в обычном цикле, после отказа обновления и при обычном перезапуске этот отчёт не вызывается. Поэтому удаление Cloud сохраняет мониторинг, но последующее обновление CH3 требует USB. Клиент и сервер блокируют несовместимую удалённую очередь для CH3 MSI-1, не изменяя пины, код или гранты.

Все три образа находятся в закрытом хранилище MSI. Проверена их реальная загрузка через публичный HTTPS-шлюз сайта: HTTP200, точные размеры и SHA-256. У CH3 были отказы download_timeout на 69%/31%, stage_sync_failed и download_http_status; последняя попытка `d01c6150-fd8e-4b7f-b4a5-f7f01cf1e1a0` завершилась без установки. Хранилище вернуло HTTP200, origin 319 мс; активные отчёты также HTTP200. Контроллер после переподключения восстановил обычные пакеты с прежней загрузкой. Временный приём двух отказов до выдачи manifest завершён, исходный bridge восстановлен; активный mode=local вообще не использует Cloud bridge. Ключи, HMAC, код, сроки свежести и разрешения не обходились. USB-пакет и ограничения описаны в CH3_USB_README_RU.md; автономные проверки пройдены на Owner и MSI, физическая запись не выполнена.

Полные checksum, добавленная SHA, модель, версия, запас OTA и совпадение разметки с установленной версией проверены. В образах отсутствует `.supabase.co`; телеметрия, отчёты OTA и загрузка будущих обновлений используют HTTPS443 Farmplast → MSI с проверкой GTS Root R1. Пины, датчики/PLC, логика управления, проверка HMAC и восстановление предыдущего слота сохранены.

Файлы: `C:\Users\Owner\AppData\Local\FarmplastMsi20261116\build\ch1v2\Chiller1.ino.bin`, аналогично `ch2v2\Chiller2.ino.bin` и `ch3v2\Chiller3.ino.bin`. Они содержат текущие Wi-Fi, ключи устройства и MSI. Последняя успешная доставка CH1/CH2 прошла через прежние закрытые bucket Supabase; все временные и старые облачные файлы удалены вместе с bucket. CH3 получает подготовленный MSI-2 через закрытый USB-пакет при появлении доступа.

CH1/CH2 установлены по одному с кратким перезапуском. Код программирования владелец вводил в форму сайта. Для обоих подтверждены новая версия, новый boot ID, прямая телеметрия и завершённый OTA. CH3 не объявляется обновлённым: USB-пакет подготовлен, ограничение последующих обновлений через USB явно принято владельцем перед удалением Cloud.

На MSI сохраняются только настройки, ключи, разрешённые операторы, ограниченные OTA receipts, задания/подписи и файлы прошивок. Таблиц измерений и старых writers в локальной схеме нет. Показания остаются только в RAM. Автономные тесты проверяют код доступа, чтение сохранённых байтов, подписи, ограниченную ссылку и подтверждение по новой загрузке и реальной телеметрии.

Удалены Edge Functions `ch1-ota`/`chiller-ota`, bucket `ch1-firmware`/`chiller-firmware` со всеми 18 файлами через интерфейс Storage, девять пользовательских OTA-секретов и все целевые SQL-объекты. Миграция `20261117043118_farmplast_remove_cloud_chillers` успешно применена одной транзакцией без CASCADE. Общий overview бочек переписан с сохранением типов столбцов, mapping и freshness. Остались две бочки/14 points/четыре latest-строки, 73 сотрудника, два Auth-пользователя и прежний ZKT cron. Аудит показывает ноль всех категорий целевых объектов; контрольные суммы несвязанных столбцов и функций совпали. Default secrets и два других bucket сохранены.

Каталог дополнительно проверен по определениям функций, представлений и политик. Удалены CH1-обработчик `apply_device_command_v2` и его триггер на общей `device_commands`; сама таблица сохранена. Из общих `cleanup_1day`/`cleanup_old_telemetry` удалены только старые ветви ch2/ch3, прочее поведение сохранено. Guards транзакции подтвердили принятые CH1/CH2 MSI-2, неактивный CH3 MSI-1 после последнего отказа, отсутствие активных OTA и предварительное удаление обоих bucket через Storage API/UI. Удалено 18 объектов: 4 CH1 и 14 CH2/CH3. Файл миграции приведён к фактической версии в истории MCP, без повторного применения.
