# Farmplast NJ → MSI: чиллеры перенесены, бочки подготовлены

Состояние на 16 ноября 2026, America/New_York (операционные отметки в UTC — 17 ноября).

Три чиллера передают данные напрямую на MSI. CH1 и CH2 обновлены до `ch1-msi-2` / `ch2-msi-2`; подтверждены новые boot ID и завершённые OTA. CH3 остаётся на `ch3-msi-1`: его мониторинг совместим с локальным обработчиком, а следующее обновление потребует подготовленного USB-пакета. Владелец явно принял это ограничение перед окончательным удалением Cloud. Сайт https://farmplast.vercel.app/monitoring/nj после очистки показывает все пять устройств онлайн: чиллеры с MSI, бочки пока через Supabase.

## Текущая схема

Устройства → HTTPS443 `/api/nj-ingest/chiller-N` сайта Farmplast → защищённый MSI. Показания больше не проходят через Supabase. Node-приёмник хранит только текущий ограниченный снимок в RAM, не записывает измерения в БД, файлы или журнал запросов. CH1 устаревает через 16 секунд, CH2/CH3 через 45 секунд, бочки после будущего переключения через 35 секунд. Просроченные значения удаляются из памяти.

Сайт читает данные через серверный API Vercel с проверкой действующего пользователя Supabase Auth и списком разрешённых UUID. Ключ MSI находится только на сервере. Ответы имеют `no-store`. Историческое соответствие двух бочек сохранено: экранная бочка 1 ← BARREL-NJ-02; экранная бочка 2 ← BARREL-NJ-01.

Служба на MSI: `E:\SimScopeData\Farmplast\NJTelemetry`, loopback `127.0.0.1:18220`, публичный HTTPS `https://msi.tail4626fb.ts.net:10000`. Задача `Farmplast-NJ-Telemetry` работает от LOCAL SERVICE и запускается при старте Windows без входа пользователя. Выполнен реальный перезапуск только этой службы: первый ответ содержал нулевые счётчики, пустые показания и OFFLINE; последующие реальные пакеты восстановили три потока. Физическая перезагрузка всего MSI не выполнялась. Порты Hvac и AI Manager сохранены.

Control/OTA, настройки, разрешённые операторы, bcrypt-код доступа и закрытые файлы обновлений также перенесены на MSI. Включён `control.mode=local`, свойства `cloud` в активной конфигурации нет. Сайт использует локальные RPC/storage через защищённый серверный шлюз. Подписи, контроль доступа и код сохранены; команды выходов, уставок и reset при проверках не отправлялись. В Supabase остаются Auth, кадровые/расчётные данные, PA climate и две бочки.

## Очистка старых измерений

После проверки новых прошивок и прямого потока выполнен `cleanup-chiller-samples.sql` с проверкой свежих receipts и завершённых OTA-заданий. Удалены 97 строк показаний чиллеров: `telemetry_latest` — 38, `ch2_latest` — 21, `ch3_latest` — 21, `asset_points_latest` — 17; `telemetry_latest_import` для них был пуст. Повторная проверка показывает ноль строк чиллеров во всех пяти таблицах.

Данные двух бочек пока не удалены: они обеспечивают действующий экран до USB-установки. Их два assets/devices, 14 points и четыре latest-строки сохранены. Проект Farmplast не удалён. `zkt_identifier_history` относится к кадровой системе и не затронута.

17 ноября в 04:31 UTC (16 ноября, America/New_York) окончательно удалены Edge Functions `ch1-ota`/`chiller-ota`, оба firmware-bucket и все 18 объектов, девять пользовательских OTA-секретов, три private-схемы чиллеров, 21 отдельная публичная таблица, их RPC/триггеры/views/политики, три assets/devices и 265 points. Общий overview переписан для двух бочек. Старые ветви ch2/ch3 удалены из общих retention-функций; общий CH1-триггер снят без удаления общей command-таблицы. Никакой Cloud-откат на MSI-1 не предлагается; CH3 обновляется через USB.

Повторный аудит `audit-cloud-chiller-removal.sql` показывает ноль целевых схем, таблиц, функций/ссылок, представлений, политик, assets/devices/points, firmware-bucket/objects. Сохранены 73 сотрудника и два Auth-пользователя. Контрольные суммы несвязанных столбцов и определений функций совпали до/после; единственный cron `cleanup_zkt_bridge_commands` сохранён. Новых категорий Security Advisor не появилось, прежние HR/Auth-предупреждения не изменялись в рамках переноса. Подробности и ограничения — `NO_CLOUD_REVIEW_RU.md`, итоговые операционные метаданные — `cloud-chiller-removal-20261116.json`.

## Chiller 3: следующий этап по USB

Обычные пакеты MSI-1 продолжают поступать на MSI без Cloud. Старые адреса Cloud используются этой прошивкой только при активной попытке обновления; такие попытки блокируются и на сайте, и на локальном сервере до USB-перехода. После появления `ch3-msi-2` программирование по сети включится автоматически. Пакет `ch3-usb` проверен автономно на Owner и MSI; физическая плата/USB-запись не испытаны. Инструкция — `CH3_USB_README_RU.md`. Перезапускать для неё нужно отдельный ESP32-шлюз, а не чиллер/PLC.

## USB-пакет для двух бочек

Подготовлен и скомпилирован `barrels-msi-1` для Waveshare ESP32-S3-Touch-LCD-7, ESP32-S3, 8 MB flash, PSRAM OPI, USB CDC. ESP32 core 3.3.8; ESP32_Display_Panel 1.0.4. Реальный исходник владельца проверен по SHA, выбранная конфигурация панели подтверждена зависимостями скомпилированных библиотек. Размер приложения 1 157 664 байта, SHA-256 `7f01930d87c96f8aa16ba53c78dec6193b5d8db0e891ed5df81b63db972eb1ce`. Полный checksum и добавленная SHA прошли проверку.

Пакет содержит приложение, таблицу разделов для сравнения, служебный boot_app0, esptool 5.2.0, установщик и инструкцию. По умолчанию выполняется только автономная проверка без COM. Запись требует явного порта, подтверждения платы и исходника, резервной копии flash и точного совпадения существующей разметки. Загрузчик, NVS и калибровки не перезаписываются. При несовпадении разметки установка останавливается до записи.

Приватный пакет на MSI: `E:\SimScopeData\Farmplast\NJTelemetry\private\firmware-20261116\barrels-usb`. Доступ только MSI\sandr и SYSTEM. Локальная копия: `C:\Users\Owner\AppData\Local\FarmplastMsi20261116\barrels-usb`. Бинарные файлы и Wi-Fi/ключи в Git не публикуются. Автономная проверка пакета пройдена на Owner и MSI.

Физического доступа к контроллеру сейчас нет. Поэтому прошивка бочек не установлена, соответствие реально установленного исходника и платы не подтверждено, USB-запись/восстановление на оборудовании не испытаны. После подключения следовать `USB_README_RU.md`, проверить оба датчика и прямое получение MSI, затем добавить бочки к `NJ_TELEMETRY_MSI_ASSETS` в Vercel, проверить сайт и удалить старые строки бочек. До этого действующий источник бочек сохраняется.

## Проверки

Пройден реальный путь контроллер → HTTPS443 → MSI RAM → авторизованный браузер после удаления всех Cloud-объектов. Все пять устройств онлайн. CH1/CH2 MSI-2 приняты, CH3 MSI-1 подтверждён живыми пакетами на локальном обработчике. Контролируемый перезапуск локальной службы дал 0 batches/points в RAM, сохранил версию, завершённое OTA и релизы в метаданных, затем реальные пакеты восстановили потоки. Закрытая загрузка всех трёх MSI-2 через публичный шлюз вернула HTTP200, точные размеры и SHA-256.

18 целевых тестов покрывают SDK → web API → RAM-приёмник, проекции и фильтры, нулевой/частичный уровень бочек, изоляцию ключей, атомарный отказ неверного пакета, сроки истечения, OTA/control adapter и реальный SQL с PGlite. Также прошли 7 проверок CH1 upload/approval и 2 проверки отображения программирования. Сборка клиента и ESLint изменённых JS/JSX проходили перед публикацией PR #28 (main d45bc3e9ce494f9115b348e29df3f3421c216fac).

Общий ESLint содержит 44 исходные ошибки в собранном `public/pa-climate/serial-loader.js` и 6 предупреждений вне изменений. Девять ZKT-тестов останавливает защитная проверка прежнего compatibility baseline; это воспроизведено на исходном f657a91. Эти кадровые SQL и проверки не изменялись. Весь проект целиком не объявляется зелёным по результатам целевых проверок переноса.
